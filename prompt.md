# Project

- I am planning to build a product called Integrated Architecture Environment (IAE)
- It gives users a real-time AI-assisted collaboration space for designing systems on canvas using shapes, arrows, etc.

# UI Design

- Inspired by vscode.dev or VS Code latest UI
- Left sidebar shows user's projects and right sidebar shows AI chat window

# Functional Requirements

### MVP

- Multiple users can collaborate on a single canvas
- AI can generate diagrams from scratch
- User has to be authenticated
- Users can generate specs markdown from diagrams using AI
- Rate limiting per project for AI usage
- User can see "saved" status of the canvas

### Later versions

- AI can modify diagram
- Common system design templates
- User can see other's cursors in real-time (implemented)
- Users can leave comments on canvas 
- Subscription

# Non-Functional Requirements

### MVP

- Handle ambiguous design to specs conversion? for eg: when a user draws vague diagram, how does AI handle the conversion?
- AI response generation should be reasonably fast

### Later versions

- Ensure "saved status of canvas snapshot" is consistent
- Handle bottlenecks like:
    - High write throughput
    - User upsert on every authenticated request
- Manage context window if we decide user can iterate with AI in a chat window

# Design

- I have come up with the entities which would be used in the backend APIs (HTTP + Web Socket). I am open to discussion if something needs be modified
    - user
    - diagram (rooms can handled using diagram_id, actual diagrams using json generated by tldraw canvas)
    - diagram_to_user mapping for getting rooms/projects per user
    - ai_generation (for AI job tracking)
- tldraw and Yjs are integrated and handle real-time collaboration
- For authentication, client and Clerk connect for auth token and the backend verifies the token with Clerk on every authenticated request. Users sign in and sign up with Google or email + OTP.

# Tech Stack

- Typescript
- Next frontend in ./frontend/
- Tailwind CSS
- UI library like shadcn to prevent reinventing the wheel
- tldraw canvas library
- Vercel for frontend deployment
- GitHub actions for CI/CD

- Express backend in ./backend/
- Clerk auth (Google or email + OTP for sign-in and sign-up)
- Yjs for real-time collaboration on the backend
- Trigger.dev for running background AI jobs on the backend
- OpenRouter/Groq for free LLM inference and AI gateway
- Supabase/Postgres as a RDBMS 
- Prisma ORM on the backend for connecting to Supabase
- Docker & Dockerhub for containerization and image repository
